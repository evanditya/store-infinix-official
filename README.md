# Infinix Official Shop Store

Full-featured e-commerce marketplace generated by **STM Converter**. Built with Next.js 14 + Python FastAPI + PostgreSQL. Includes seller dashboard, buyer registration, shopping cart, Midtrans payment, Biteship shipping, branding CMS, and automated email notifications.

---

## Quick Start (Replit) — Recommended

### Step 1: Import Repository
1. Go to [replit.com](https://replit.com) and click **Create Repl**
2. Select **Import from GitHub**
3. Paste this repository URL and click **Import from GitHub**

### Step 2: Add PostgreSQL Database
1. In your Repl, open the **Tools** panel (left sidebar)
2. Search for **PostgreSQL** and click **Add**
3. `DATABASE_URL` will be set automatically

### Step 3: Add Secrets
Open the **Secrets** tab and add the keys you need:

| Secret | Required | Description | Where to Get |
|---|---|---|---|
| `MIDTRANS_SERVER_KEY` | For payments | Midtrans server key | [Midtrans Dashboard](https://dashboard.sandbox.midtrans.com) › Settings › Access Keys |
| `MIDTRANS_CLIENT_KEY` | For payments | Midtrans client key | Same as above |
| `MIDTRANS_IS_PRODUCTION` | No | `true` for live payments | Set manually (default `false`) |
| `BITESHIP_API_KEY` | For shipping | Biteship API key | [Biteship Dashboard](https://biteship.com) › Settings › API Keys |
| `EMAIL_HOST` | For emails | SMTP server hostname | e.g. `smtp.gmail.com` |
| `EMAIL_PORT` | For emails | SMTP port | `587` (TLS) |
| `EMAIL_USER` | For emails | SMTP username / email address | Your email address |
| `EMAIL_PASSWORD` | For emails | SMTP password or App Password | Gmail: use an App Password |
| `EMAIL_FROM_NAME` | No | Sender name shown to buyers | Defaults to store name |
| `SESSION_SECRET` | No | JWT signing secret | Auto-generated if not set |

> **Tip — Gmail App Password**: Go to your Google Account › Security › 2-Step Verification › App passwords. Generate one for "Mail" and paste it as `EMAIL_PASSWORD`. Do **not** use your regular Gmail password.

### Step 4: Run
Click the **Run** button. The app will automatically:
- Install all dependencies
- Set up database tables
- Seed product data from `backend/seed_data.json`
- Start the frontend (port 5000) and backend API (port 8000)

## Features

### For Buyers
- Browse product catalog with category filter, keyword search, and sort options
- View detailed product pages with full image gallery, variant picker, specifications table, and description images
- **Smart variant selection**: add-to-cart is disabled until all required variants are chosen; price range displayed before selection when variants have different prices
- Add to cart with per-variant quantity control
- Checkout with address search, real-time courier rate comparison, and Midtrans Snap payment popup
- Order history with **4 status tabs**: Semua / Belum Dibayar / Dikemas / Dikirim
- In-page shipment tracking with step-by-step history timeline
- **Automated email notifications** at key order lifecycle events (see below)

### For Sellers (Super Admin)
- Dashboard with sales overview and real-time order management
- Product management: create, edit, and delete products with bulk image upload, paginated listing, and keyword search
- Manage product variants (size, color, model, etc.) with per-variant pricing, discount, and stock — variant stocks are the single source of truth and are automatically summed into the product's total stock
- **Bulk Excel import/export** of products and variants (see *Excel Import/Export* below)
- Process orders: confirm, pack, and hand off to courier
- Create Biteship shipments, generate shipping labels, and track packages
- **Branding CMS**: customise logo, banner, favicon, primary color, accent color, font, and store name — live preview before saving
- **Homepage Banner Slider**: upload multiple banners, crop them in-browser, drag-and-drop to reorder, and toggle visibility per banner
- **Sub-Admin Management**: create staff accounts (admins) with granular per-menu permissions (Products, Orders, Banners, Settings)
- Change password

### For Sub-Admins
- Login with the same login screen as buyers/sellers — role and permissions are auto-detected
- See only the dashboard sections the super admin granted them
- Cannot create or modify other admins (super-admin-only action)

### Technical
- JWT-based authentication with three roles: `buyer`, `seller` (super admin), `admin` (sub-admin)
- Permission helpers in `backend/app/routes/auth.py`: `is_staff(user)`, `has_perm(user, perm)`, `parse_permissions(user)`
- **Auto DB migrations** on startup (`main.py → _run_migrations()`) — currently adds `users.permissions` column to legacy databases
- **Single source of truth for stock**: `effective_stock(product)` sums variant stocks; auto-synced on create, update, and Excel import
- Fully responsive design — mobile-first
- SEO-friendly with Next.js App Router metadata and Open Graph tags
- **Favicon support for all browsers including Safari** via dedicated `/api/favicon` proxy route with proper no-cache headers
- RESTful API with auto-generated Swagger docs at `/docs`
- CSS variables (`--color-primary`, `--color-accent`, `--font-store`) applied at runtime for instant branding changes
- Database seeding from `seed_data.json` on first run

## Roles & Permissions

| Role | Can Login? | Capabilities |
|---|---|---|
| `buyer` | Yes | Shop, checkout, view own orders |
| `seller` | Yes | **Super Admin** — full dashboard access, manages sub-admins, products, orders, branding, banners, settings |
| `admin` | Yes | **Sub-Admin** — only the menus the super admin granted (any subset of `products`, `orders`, `banners`, `settings`) |

Permissions are stored as a JSON array on `users.permissions` (TEXT). Editing permissions instantly takes effect on the sub-admin's next page load.

## Pricing Conventions

The store uses the same convention for both products and variants:

| Field | Meaning | Display |
|---|---|---|
| `price` | **Harga Asli** (full / normal price) | Shown crossed out when a discount is set |
| `original_price` | **Harga Diskon** (selling price, optional) | Shown as the main price when set; must be lower than `price` to qualify as a discount |

A discount is rendered only when `original_price` is set **and** lower than `price`. Otherwise, `price` is shown alone with no strikethrough. The discount badge percentage is computed as `1 - (original_price / price)`.

## Excel Import/Export

Bulk-edit your catalogue from the seller dashboard → **Produk** tab:

- **Export**: download an `.xlsx` workbook with two sheets:
  - *Sheet 1 — Produk*: one row per product (Nama, Kategori, Harga, Harga Coret, Stok, dimensions, etc.)
  - *Sheet 2 — Varian*: one row per variant (Nama Produk, Nama Varian, **Harga Asli**, **Harga Diskon**, Stok, Tersedia)
- **Import**: edit the file in Excel/Sheets and re-upload. Changes are matched by product slug and variant name. Backwards-compatible with files using the old `Harga` / `Harga Coret` column names.
- **Validation**: rows with missing required fields are reported back; valid rows are still applied

## Email Notifications

The store sends HTML email notifications to buyers at three lifecycle stages. All emails are sent asynchronously (background thread) and are silently skipped if SMTP is not configured.

| Trigger | Email Subject | Content |
|---|---|---|
| Order placed (checkout) | `Pesanan #XXXXXXXX — Menunggu Pembayaran` | Order summary, product list, shipping address, payment instructions |
| Payment confirmed (Midtrans webhook or status poll) | `Pesanan #XXXXXXXX — Pembayaran Berhasil` | Payment confirmation, order total, resi number if available |
| Seller marks order as Completed | `Pesanan #XXXXXXXX — Barang Diterima` | Order recap and thank-you message |

### Configuring Email

Add these to your Secrets / `.env.local`:

```env
EMAIL_HOST=smtp.gmail.com      # or smtp.brevo.com, in-v3.mailjet.com, etc.
EMAIL_PORT=587
EMAIL_USER=your@gmail.com
EMAIL_PASSWORD=xxxx-xxxx-xxxx  # Gmail App Password (not your regular password)
EMAIL_FROM_NAME=Infinix Official Shop  # Display name shown to buyers
```

If any of `EMAIL_HOST`, `EMAIL_USER`, or `EMAIL_PASSWORD` is blank, the email feature is disabled and the rest of the store works normally.

## Payment Gateway — Midtrans

### Setup

1. **Create Account**: [midtrans.com](https://midtrans.com)
2. **Get API Keys**:
   - Sandbox (testing): [dashboard.sandbox.midtrans.com](https://dashboard.sandbox.midtrans.com) › Settings › Access Keys
   - Production (live): [dashboard.midtrans.com](https://dashboard.midtrans.com) › Settings › Access Keys
3. **Add to Secrets**:
   ```
   MIDTRANS_SERVER_KEY = <your server key>
   MIDTRANS_CLIENT_KEY = <your client key>
   MIDTRANS_IS_PRODUCTION = false   # change to true when going live
   ```

### Midtrans Dashboard — Required URL Configuration

You must set these URLs in your Midtrans Dashboard so that payments are confirmed and buyers are redirected correctly.

**Step 1 — Payment Notification (Webhook)**
Go to **Settings › Configuration** and set:

| Field | Value |
|---|---|
| Payment Notification URL | `https://your-domain.replit.app/api/payment/notification` |

> This webhook is called by Midtrans every time a payment status changes (paid, expired, cancelled, etc.). Without it, order status will only update when the buyer manually checks their order page.

**Step 2 — Snap Redirect URLs**
Go to **Settings › Snap Preferences** and set:

| Field | Value |
|---|---|
| Finish Redirect URL | `https://your-domain.replit.app/orders` |
| Unfinish Redirect URL | `https://your-domain.replit.app/checkout` |
| Error Redirect URL | `https://your-domain.replit.app/checkout` |

> Replace `your-domain.replit.app` with your actual Replit app domain (shown in the browser after clicking **Deploy** or **Run**). Use the same domain for both sandbox and production — just switch the API keys.

## Troubleshooting

### App won't start
- On Replit: make sure PostgreSQL was added from the Tools menu
- Check that `DATABASE_URL` is set in Secrets

### Payment not working
- Verify `MIDTRANS_SERVER_KEY` and `MIDTRANS_CLIENT_KEY` are correct
- Use sandbox keys for testing, production keys for live
- Check Midtrans Dashboard transaction logs for error details

### Shipping rates not loading
- Verify `BITESHIP_API_KEY` is active in Biteship Dashboard
- Make sure you set a seller origin (city + postal code) in Dashboard › Shipping Settings

### Emails not arriving
- Verify all three email secrets are set (`EMAIL_HOST`, `EMAIL_USER`, `EMAIL_PASSWORD` minimum)
- For Gmail: use an App Password (not your regular password), and enable 2-Step Verification first
- Check the backend console logs for `[email]` lines
- Test your SMTP credentials with a tool like [smtp4dev](https://smtp4dev.com) or [Mailtrap](https://mailtrap.io)

### Favicon not showing in Safari
- Safari requires explicit `<link rel="apple-touch-icon">` tags — these are already present in `layout.tsx`
- Hard-refresh the page (Cmd+Shift+R on macOS / Ctrl+Shift+R on Windows)
